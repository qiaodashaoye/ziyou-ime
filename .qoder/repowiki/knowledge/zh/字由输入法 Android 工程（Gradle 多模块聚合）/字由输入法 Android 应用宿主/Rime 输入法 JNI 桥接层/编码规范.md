- JNI 字符串与本地字符串互转统一通过 RAII 包装器 `CString`、`JString`、`JRef<jobject>` 管理，避免手动 `GetStringUTFChars` / `DeleteLocalRef` 泄漏。
- 所有 JNI 导出函数遵循 `Java_com_ziyou_ime_core_<ClassName>_<methodName>` 命名规范，参数类型与返回值严格对应 Java 侧 `RimeNative` / `RimeConfig` 接口。
- C++ 数据结构（CommitProto/ContextProto/StatusProto/CandidateProto/SchemaItem）采用从 `Rime*` C 结构体构造的显式构造函数，空指针字段统一回退为空字符串或默认值。
- Java 对象创建统一通过 `GlobalRefSingleton` 缓存的 jclass 与 jmethodID 调用构造函数，避免重复 `FindClass` / `GetMethodID` 开销。
- 可选功能通过 CMake `option(WITH_*)` 配合 `#ifdef WITH_*` 条件编译，并在 `declare_librime_module_dependencies()` 中集中声明模块依赖。
- 资源生命周期采用 RAII 模式：`SessionHolder` 自动销毁会话、`CString`/`JString`/`JRef` 自动释放 JNI 引用，异常路径通过 `std::runtime_error` 抛出。
