# 字由输入法 · 等级体系可行性方案

> 版本：v1.0　｜　定位：在不破坏输入法"高频刚需工具"体验的前提下，用**克制的激励**提升粘性与趣味性。
> 本文档在原始设计方案基础上，结合字由输入法现有架构（见 `ARCHITECTURE.md`）给出修订、改进与落地路径。

---

## 1. 总体评价

原方案产品直觉优秀，四条核心原则（隐私至上、奖励努力不惩罚、成长感清晰、离线可用）应完整保留。但存在若干**内部矛盾**与**与本项目技术现实不符**之处，需修正后落地：

1. **计分口径**应从"按键次数"改为"上屏字符数"，更公平、更省电、天然脱敏。
2. **"只增不减"与"30 天回退进度"自相矛盾**，需二选一（本文选择不回退，改用活跃状态衰减）。
3. **每日上限 2000 分偏低**，会让核心重度用户过早触顶。
4. **等级曲线与每日上限打架**，需重设曲线并引入满级后的持续目标。
5. **词库容量、剪贴板条数等核心能力不应锁进等级**，否则被视为"人为阉割"。
6. **联网校时 / 看广告补签**与"离线优先/隐私至上"冲突，应作为可选项默认关闭。

---

## 2. 保留的核心设计原则

| 原则 | 说明 |
|---|---|
| 隐私至上 | 绝不记录输入内容，只统计脱敏聚合计数（字数、时长、频次、时段） |
| 奖励努力，不惩罚 | 积分只增不减，无掉段；不活跃只影响"活跃状态"标识，不动等级与进度 |
| 成长感清晰 | 明确"距下一级还差多少"与"升级解锁什么" |
| 离线优先 | 计分、判级全部本地完成，联网仅做加密备份/同步（可选） |
| 权益解痒 | 奖励与输入体验挂钩，但只解锁"锦上添花"，不阉割核心能力 |

## 3. 计分机制（修订版）

### 3.1 计分口径：以"上屏字符数"为准

**关键改进**：不统计按键次数，而是在**文本真正上屏（`commitText`）时按 Unicode code point 计数**。原因：

- 退格、编码中途、翻页等不产生上屏，不应计分 → 更公平，天然防刷。
- 一次选词可上屏多个字（词/短语），按结果计分符合直觉。
- 只需 `text.codePointCount()`，不触碰内容 → 天然脱敏、极省电。

> 本项目所有上屏都汇聚到 `SimpleRimeInputMethodService` 的 4 处 `commitText` 调用（普通提交、直接字符提交、候选词提交、符号提交）。落地时统一收敛到一个 `commitAndCount(text)` 私有方法即可。

### 3.2 积分表（修订）

| 行为大类 | 具体行为 | 单次积分 | 每日上限 |
|---|---|---|---|
| 基础输入 | 上屏 1 个字符（中/英） | 1 分 | **分段递减**：前 2000 字全额，2000–6000 字半额，超出 0 分 |
| 每日首用 | 当日首次唤起键盘并上屏 | 10 分 | 日限 1 次 |
| 连续天数 | 连续使用第 N 天 | 第 2 天 +5，逐日 +5，封顶 +30/天；第 7 天额外 +50 | 7 天一循环，中断重置 |
| 功能探索 | 语音/手写/翻译/表情/滑动等特色功能 | 每次 20 分 | 每种功能每日限 3 次 |
| 效率行为 | 快捷短语、剪贴板、滑动输入 | 每次 5 分 | 每日上限 100 分 |
| 成就任务 | 一次性成就（累计 1 万字等） | 100–500 分 | 不设限 |
| 社区互动（可选） | 分享自创短语/表情 | 每次 30 分 | 日限 5 次 |

**改进说明**：
- 用**分段递减**替代硬上限 2000。重度用户日输入可达数千~上万字，硬上限会让他们午后就"打字无意义"，反而流失。分段递减既防刷分机器人，又不惩罚真实高产用户。
- 连续天数封顶 +30/天，避免线性膨胀。
- 社区互动、看广告补签属**联网/商业化**，默认关闭，作为 v2+ 可选。

## 4. 等级与权益体系（修订版）

### 4.1 等级曲线重设

原曲线（Lv20=50000）与日上限冲突：按每日约 2000 有效分，25 天即可封顶，之后失去目标。修订为：

- **1–20 级**：指数递增，中重度用户约 2–4 个月自然到达 Lv20，节奏"前快后慢"。
- **Lv20 之后**：引入**"声望值 / 赛季"**——不再涨级，改为累积可展示的声望徽章与季度荣誉，提供长期目标，规避天花板。

| 等级 | 名称 | 累计积分 | 核心解锁权益（仅锦上添花） |
|---|---|---|---|
| Lv.1 | 初识键盘 | 0 | 基础皮肤、默认音效 |
| Lv.2 | 键客入门 | 100 | 主题皮肤 ×1 |
| Lv.3 | 指尖舞者 | 300 | 键盘徽章样式 ×1 |
| Lv.4 | 码字学徒 | 700 | 自定义短语槽位 +5（在默认额度之上） |
| Lv.5 | 连击高手 | 1400 | 按键音效包 ×1 |
| Lv.6 | 效率专员 | 2500 | 周输入统计报告 |
| Lv.7 | 键盘侠客 | 4200 | 皮肤 ×1、字体大小档位解锁 |
| Lv.8 | 文字猎手 | 6800 | 剪贴板收藏槽位扩展（非基础容量） |
| Lv.9 | 灵感速记 | 10500 | 动态皮肤 ×1 |
| Lv.10 | 输入达人 | 16000 | 自定义键盘背景图 |
| … | … | … | … |
| Lv.20 | 码神降临 | 120000 | 专属尊贵标识、全部音效、内测优先、开启声望赛季 |

> 曲线为示例，需在灰度中根据真实日活分布调参。

### 4.2 权益设计红线（重要修订）

**核心能力默认给足，等级只解锁"外观 / 荣誉 / 增量槽位"**：

- ✅ 可挂等级：皮肤、音效、字体档位、键盘徽章、动态皮肤、背景图、统计报告、**自定义短语/剪贴板收藏的"额外槽位"**、内测资格、尊贵标识。
- ❌ 禁止挂等级：**词库容量、剪贴板基础条数、预测/联想准确率、联想速度**等核心输入能力。这些默认给足；把它们锁在等级后会被理解为"故意做残再让你解锁"，引发强烈反感。

> 原方案中"词库容量+500""剪贴板增至50条"属于核心能力，应下放为默认值；等级只提供"在默认之上的额外槽位/收藏夹"这类增量。

## 5. UI 与交互反馈

原则：**克制地展示，喜悦地反馈，绝不霸屏。**

- **等级入口**：放在"我的/设置"页面（`SettingsActivity`）与键盘工具栏二级菜单，一个精致徽章，点开见详情。
- **升级瞬间**：候选栏上方或键盘区顶部临时飘出轻盈动画（勋章弹出/微烟花）≈1.5s + 可选音效，随后自动消失，**不弹窗**。
- **进度显示**：个人中心显示经验条 `Lv.7 键盘侠客 4200/6800`。
- **每日简报**：次日首次唤起键盘时，用极小条状提示"昨日 1280 字 · +1280 分 · 连续第 5 天"，2 秒后自动消失，点击可展开。
- **触顶关怀**：当日有效分达段位上限时，友好提示"今日已尽兴，注意休息，明日再战"，把"上限"包装成关怀而非剥夺。

## 6. 技术实现方案（结合本项目架构）

### 6.1 分层落点

依赖方向沿用 `UI → IME → Core → JNI → Engine`，等级模块作为**独立的旁路特性**，不侵入 Rime 热路径逻辑：

```
新增 gamification 包（建议 com.ziyou.ime.level）
├── LevelStats         // 内存计数器（O(1) 自增），单例
├── LevelRepository    // 持久化：SharedPreferences + JSON（对齐 SideSymbol 惯例）
├── LevelEngine        // 积分→等级判定、曲线表、每日重置、连续天数
├── AchievementManager // 一次性成就与隐藏彩蛋（脱敏聚合判定）
└── LevelUiState       // 供 UI 层观察的 StateFlow（等级/进度/简报）
```

### 6.2 计分挂钩点（最小侵入）

将 `SimpleRimeInputMethodService` 中 4 处 `commitText(...)` 收敛为单一私有方法并埋点：

```kotlin
private fun commitAndCount(text: CharSequence) {
    currentInputConnection?.commitText(text, 1)
    // 热路径：仅做内存自增，绝不在此写磁盘
    LevelStats.onCommit(text.codePointCount(0, text.length))
}
```

- `LevelStats.onCommit` 只做 `AtomicLong` 自增等 O(1) 操作。
- **防抖落盘**：由 `LevelRepository` 每 N 次（如 200）或每 60 秒 flush 一次，或在 `onFinishInputView`/`onDestroy` 生命周期回调时 flush，避免高频 `SharedPreferences.apply`。

### 6.3 持久化选型

沿用项目现有惯例（无 Room，`SharedPreferences` + JSON，见 `SideSymbol.kt`、`ThemeManager.kt`）：

- 计数器与等级状态：`SharedPreferences`（累计分、当前等级、当日分、当日日期、连续天数、上次活跃日）。
- 成就解锁集合、赛季声望：JSON 序列化存入同一 prefs。
- **进程一致性（已确认）**：核查 `AndroidManifest.xml`，`SimpleRimeInputMethodService`、`SettingsActivity`、`DictManagerActivity` 均未声明 `android:process`，同属应用默认主进程。因此三者共享同一份 `SharedPreferences` 实例、数据一致，**无需引入 DataStore 解决跨进程问题**，`SharedPreferences` + JSON 方案可行。
- **未来拆进程需重新评估**：若后续为稳定性将 IME 拆到独立进程（`android:process=":ime"`），`SharedPreferences` 跨进程不可靠（`MODE_MULTI_PROCESS` 已废弃），届时应改用单一数据源 + 显式跨进程通知。

### 6.4 与现有系统的联动

- **皮肤/音效解锁** → 复用 `ThemeManager`，按等级过滤可选主题列表。
- **自定义短语/剪贴板增量槽位** → 在 `SideSymbol`/短语相关存储的额度上叠加等级增量。
- **统计报告** → 直接读取 `LevelRepository` 的聚合计数渲染。

## 7. 隐私与防作弊

### 7.1 隐私（硬约束）

- 只维护**计数器**：上屏字符数、时长桶、功能使用次数、时段计数、中英字符占比计数——**从不存储任何字符内容、上下文或所在应用**。
- 成就判定（夜猫子=凌晨时段计数、语言通=中英字符区间计数）同样只累加聚合数，不落内容。
- 隐私政策与首启弹窗明确告知："统计总字数、使用时长等，仅用于本地等级计算，不上传任何输入内容。"
- 联网同步（可选）：仅上传**加密后的积分数字与等级**，绝不含内容。

### 7.2 防作弊 / 防时间篡改

- 每日重置以本地日期为准，同时记录 `SystemClock.elapsedRealtime()`（不可回拨）与墙钟。检测到墙钟大幅回拨/前跳时，**暂停当日积分累积**直到恢复，而非直接封禁。
- 联网校时**可选、默认关闭**；开启后以服务器时间为准。离线用户不受影响。
- 分段递减 + 每日上限本身即是主要的防刷手段。

## 8. 分阶段实施路线

### MVP（v1，2–3 周，纯本地）
- `LevelStats` + `LevelRepository` + `LevelEngine`，`commitText` 埋点计数。
- 基础积分：上屏字符数（分段递减）、每日首用、连续天数。
- 1–10 级曲线 + 皮肤/音效解锁（复用 `ThemeManager`）。
- 设置页等级卡片 + 经验条；升级轻动画；每日简报。
- 隐私政策文案与首启告知。

### v2（增强，2–3 周）
- 功能探索/效率行为积分、一次性成就、隐藏彩蛋。
- 11–20 级 + 增量槽位类权益、统计报告。
- 防时间篡改逻辑。

### v3（可选，联网/商业化）
- 加密积分云备份/多端同步。
- 看广告补签、积分兑换高级皮肤（需与"离线优先"平衡，默认克制）。
- 声望赛季与社区分享。

## 9. 风险与取舍

| 风险 | 应对 |
|---|---|
| 热路径埋点影响输入延迟 | 仅内存自增 + 防抖落盘；压测 commit 路径 P99 无回归 |
| "打工感"、被上限剥夺感 | 分段递减替代硬上限；触顶做关怀式文案 |
| 核心能力被锁引发反感 | 权益红线：只解锁外观/荣誉/增量槽位 |
| 进度回退挫败 | 取消进度回退，仅衰减"活跃状态"标识 |
| 曲线封顶后无目标 | Lv20 后引入声望/赛季长期目标 |
| 隐私质疑 | 只存计数、政策透明、同步仅传密文数字 |
| 跨进程数据不一致 | 落地前确认 IME 与设置页进程模型 |

data class LevelState(
    val totalPoints: Long = 0,      // 累计积分（只增不减）

data class AggregateCounters(

    val enChars: Long = 0,        // 英文字符累计

## 结论

该等级体系在**修正上述矛盾点**（计分口径、进度回退、每日上限、曲线天花板、核心能力不上锁）后，**技术可行且与本项目架构契合度高**：埋点集中、纯本地可运行、复用现有 `ThemeManager`/`SharedPreferences` 惯例，MVP 可在 2–3 周内低风险落地。核心成功要素是**克制**——让等级成为输入愉悦的点缀，而非打扰用户的 KPI。
