# 皮肤模块系统设计方案

> 状态：已实施（P1–P4 全部落地；ThemeManager/KeyboardTheme 已删除）
> 实施偏差：内置三皮肤规格以内存常量实现（core.skin.SkinDefaults），不再经
> assets/skins 落盘部署——内置皮肤零 IO 且免增量部署链路；其余与本方案一致。
> 范围：完全移除 ThemeManager / KeyboardTheme，新建独立皮肤业务域（Skin Domain），
> 覆盖用户自定义、皮肤包加载/卸载、缓存、持久化、预览与运行时切换。

---

## 1. 背景与目标

当前主题系统的局限（`app/src/main/java/com/ziyou/ime/config/ThemeManager.kt`）：

| 现状 | 局限 |
|------|------|
| `KeyboardTheme` 仅 9 个纯色字段 | 无法表达字号、圆角、间距、阴影、图片背景、透明度 |
| 3 个预设主题硬编码在 Kotlin 源码 | 不可扩展、不可分发、用户不可自定义 |
| `ThemeManager` object + SharedPreferences 存主题名 | 无皮肤包概念，无安装/卸载/校验/缓存 |
| 无预览能力 | 设置页只能凭名字盲选 |

设计目标：

1. **表达力**：颜色 / 字体 / 尺寸 / 圆角 / 阴影 / 图片背景 / 透明度 / 深浅色双套配色全覆盖。
2. **可分发**：`.zyskin` 皮肤包（zip）可导入 / 卸载 / 校验，参考本项目 `.skill` 技能包的既有模式。
3. **可自定义**：用户在任意基础皮肤上叠加个性化覆盖（滑杆调圆角/透明度/字号、取色器改色），随时恢复。
4. **零热路径开销**：皮肤解析与图片解码全部发生在切换时刻的后台线程；按键→上屏热路径维持 O(1) 内存操作、无磁盘 IO（见 AGENTS.md 变更检查清单）。
5. **架构合规**：纯逻辑（解析/合并/校验/色值计算）下沉 `:core-logic`；Android 相关（zip、Bitmap、SharedPreferences、View）留在 `:app`；依赖方向保持 `:app → :core-logic` 单向。

## 2. 主流输入法皮肤方案调研结论

| 产品 | 机制要点 | 借鉴 |
|------|---------|------|
| **Google Gboard** | 内置主题 = 配色方案 + 可选背景图 + "按键边框开关"；Material You 动态取色；主题是**声明式参数集**而非代码 | 皮肤 = 纯数据（JSON），运行时解析为不可变快照；深浅色双变体 |
| **搜狗/百度输入法** | 皮肤包 = zip（配置文件 + 切图 + 预览图），皮肤商店分发；安装即解压到私有目录建立索引 | `.zyskin` = zip(skin.json + images/ + preview.png)；`filesDir/skins/<id>/` 安装目录 + 索引 |
| **OpenBoard / FlorisBoard**（开源） | 主题以 JSON/Snygg 样式表描述，属性带默认值，缺失字段回退；主题热切换重建渲染快照 | 字段全部可缺省 + 默认值链；切换复用视图重建路径 |

共同结论：**皮肤是数据不是代码**——不引入任何可执行内容，安全模型与本项目技能插件（WebView 沙箱）完全不同，皮肤包只允许 JSON + 位图 + 字体文件。

## 3. 总体架构

### 3.1 模块划分

```
:core-logic  com.ziyou.ime.core.skin        （纯 Kotlin，无 Android 依赖，可 JVM 单测）
   ├── SkinSpec.kt          皮肤规格数据模型（颜色已解析为 Int）
   ├── SkinColor.kt         "#AARRGGBB" ↔ Int 纯 Kotlin 解析（不依赖 android.graphics.Color）
   ├── SkinResolver.kt      默认值链 + 用户覆盖合并 → 解析结果（纯函数）
   ├── SkinSpecValidator.kt 语义校验（字段范围 / specVersion / id 格式），返回错误列表
   └── SkinDefaults.kt      内置皮肤规格常量（现行：悬浮立体（默认）/云雾拟态/Material）

:app  com.ziyou.ime.skin                     （皮肤业务域，对齐 level/ dict/ skill/ 的业务域划分）
   ├── SkinTheme.kt          运行时不可变快照（视图消费的唯一模型，取代 KeyboardTheme）
   ├── SkinManager.kt        门面 object（取代 ThemeManager 的全部调用点）
   ├── SkinRepository.kt     已安装皮肤索引 + 当前皮肤/用户覆盖持久化
   ├── SkinPackLoader.kt     .zyskin 导入/卸载/安全校验（zip-slip、大小、类型白名单）
   ├── SkinSpecCodec.kt      skin.json ↔ SkinSpec 的 org.json 编解码（Android 侧）
   ├── SkinAssetCache.kt     背景图/字体/预览图缓存（LruCache + 预缩放）
   ├── SkinCustomizer.kt     用户自定义覆盖的读写与重置
   └── SkinPreviewRenderer.kt 离屏渲染迷你键盘预览图（复用 TextImageRenderer 的 Canvas 模式）

:app  com.ziyou.ime.ui
   └── SkinActivity.kt       皮肤管理页（纯代码布局，预览网格 + 导入 + 自定义编辑器）
```

依赖方向（编译器强制单向）：

```
ui.SkinActivity ──▶ skin.SkinManager ──▶ core.skin.SkinResolver / SkinSpecValidator
ime.各View      ──▶ skin.SkinTheme（只读快照，不反向依赖 Manager）
skin.*          ──▶ core.level.LevelEngine（解锁判定，沿用现有能力）
```

### 3.2 数据流（皮肤生命周期）

```
 .zyskin 文件                     assets/skins/（内置）
      │ SkinPackLoader.install()        │ 首次启动部署
      ▼                                 ▼
 filesDir/skins/<skinId>/   ◀── 安装目录（skin.json + images/ + preview.png）
      │
      │ SkinRepository：索引（prefs）+ 当前皮肤 id + 用户覆盖 JSON
      ▼
 SkinSpecCodec.decode(skin.json) ──▶ SkinSpec
      │
      │ SkinResolver.resolve(spec, userOverride, isDarkMode)   ← :core-logic 纯函数
      ▼
 ResolvedSkin（全字段落定的纯数据）
      │
      │ SkinManager：+ 背景 Bitmap 解码（后台线程，SkinAssetCache）
      ▼
 SkinTheme（内存快照，volatile 缓存） ──▶ 各 View.applySkin() 重建画笔 ──▶ Canvas 绘制
```

关键不变量：**View 只见 `SkinTheme` 不可变快照**；解析、合并、IO 全部发生在快照构建时刻，
绘制帧内零解析、零 IO——与现行 `applyTheme → rebuildPaints → invalidate` 模式完全同构。

## 4. 皮肤包格式定义

### 4.1 包结构（`.zyskin` = zip）

```
com.example.ocean.zyskin
├── skin.json          # 必需，皮肤规格（UTF-8）
├── preview.png        # 必需，预览图（建议 720×480，≤ 300KB）
├── images/            # 可选，背景/纹理位图（png/jpg/webp）
│   ├── bg.png
│   └── bg_dark.png
└── fonts/             # 可选，自定义字体（ttf/otf，≤ 2MB/个）
    └── custom.ttf
```

安全约束（`SkinPackLoader` 强制执行）：

- 解压时防 zip-slip（规范化路径必须落在目标目录内）；
- 条目数 ≤ 64，单文件 ≤ 5MB，解压总量 ≤ 20MB；
- 扩展名白名单：`json / png / jpg / jpeg / webp / ttf / otf`，其余条目直接拒绝安装；
- `skin.json` 必须通过 `SkinSpecValidator` 全量校验才落盘，失败则回滚删除安装目录；
- 皮肤包**不含任何可执行内容**，不进 WebView，不解析表达式。

### 4.2 skin.json 规格（specVersion = 1）

所有字段除 `specVersion` 与 `meta.id/name` 外均可缺省，缺省值即默认值链兜底视觉
（缺字段永不崩溃，解析结果稳定可预期）。

```json
{
  "specVersion": 1,

  "meta": {
    "id": "com.example.ocean",
    "name": "海洋",
    "author": "example",
    "version": "1.0.0",
    "minSpecVersion": 1,
    "darkMode": "both"
  },

  "colors": {
    "light": {
      "keyboardBackground":      "#F5F5F5",
      "keyBackground":           "#FFFFFF",
      "keyTextColor":            "#212121",
      "keyPressedBackground":    "#E0E0E0",
      "funcKeyBackground":       null,
      "candidateBackground":     "#FFFFFF",
      "candidateTextColor":      "#212121",
      "candidateHighlightColor": "#1976D2",
      "preeditTextColor":        "#424242",
      "borderColor":             "#BDBDBD",
      "keyShadowColor":          "#22000000"
    },
    "dark": { "...同结构，darkMode=both 时必填..." : "" }
  },

  "dimens": {
    "keyCornerRadiusDp": 8.0,
    "keyGapDp":          4.0,
    "keyboardPaddingDp": 6.0,
    "keyHeightScale":    1.0,
    "keyBorderWidthDp":  0.0
  },

  "typography": {
    "keyTextSizeSp":       20.0,
    "funcTextSizeSp":      14.0,
    "candidateTextSizeSp": 18.0,
    "preeditTextSizeSp":   16.0,
    "fontFamily":          "fonts/custom.ttf",
    "keyTextBold":         false
  },

  "effects": {
    "keyStyle":        "filled",
    "keyShadow":       { "enabled": true, "radiusDp": 2.0, "dxDp": 0.0, "dyDp": 1.0 },
    "backgroundAlpha": 1.0
  },

  "background": {
    "image":     "images/bg.png",
    "imageDark": "images/bg_dark.png",
    "scaleMode": "centerCrop",
    "dimAmount": 0.0
  }
}
```

字段语义与校验规则（`SkinSpecValidator`）：

| 字段 | 语义 | 校验 |
|------|------|------|
| `meta.id` | 全局唯一 id，即安装目录名 | `[a-z0-9_.]{3,64}`，禁止与内置 id 冲突 |
| `meta.darkMode` | `light` / `dark` / `both` | `both` 时 `colors.dark` 必须完整或可从 light 派生 |
| `colors.*` | `#RRGGBB` 或 `#AARRGGBB` | `SkinColor.parse` 失败即报错；`funcKeyBackground` 为 null 时沿用现行 `blendColor(keyBackground, borderColor, 0.55)` 派生规则 |
| `dimens.keyCornerRadiusDp` | 按键圆角 | 0–24 |
| `dimens.keyGapDp` | 键间距 | 0–12 |
| `dimens.keyHeightScale` | 键高倍率（乘在现有 `keyHeightMultiplier` 之上） | 0.8–1.3 |
| `typography.*SizeSp` | 各区字号 | 8–32 |
| `typography.fontFamily` | 包内字体相对路径 | 文件必须存在于包内 `fonts/` |
| `effects.keyStyle` | `filled`（现状）/ `outline`（描边无填充）/ `flat`（无键面纯文字，Gboard 无边框风格） | 枚举 |
| `effects.backgroundAlpha` | 键面整体透明度（悬浮/游戏场景） | 0.3–1.0 |
| `background.scaleMode` | `centerCrop` / `fitXY` / `tile` | 枚举 |
| `background.dimAmount` | 背景图上的压暗遮罩（保证按键可读性） | 0–0.7 |

### 4.3 用户自定义覆盖（UserOverride）

与 skin.json 同构的**稀疏 JSON**（只存用户改过的字段），由 `SkinCustomizer` 写入
`SharedPreferences("ziyou_skin")`，键 `override.<skinId>`。示例——用户在"海洋"上调大圆角、降低透明度：

```json
{ "dimens": { "keyCornerRadiusDp": 16.0 }, "effects": { "backgroundAlpha": 0.85 } }
```

合并优先级（`SkinResolver`，纯函数）：**UserOverride > skin.json > SkinDefaults**。
恢复默认 = 删除覆盖键，基础皮肤永不被改写（皮肤包目录只读）。

## 5. 运行时模型与解析管线

### 5.1 `SkinTheme`（视图消费的唯一模型）

```kotlin
// :app com.ziyou.ime.skin —— 不可变快照，字段为最终物理值（颜色 Int / dp / sp）
class SkinTheme(
    val id: String,
    val name: String,
    // —— 颜色：与旧 KeyboardTheme 9 字段一一对应（迁移零语义变化）——
    val keyboardBackground: Int,
    val keyBackground: Int,
    val keyTextColor: Int,
    val keyPressedBackground: Int,
    val funcKeyBackground: Int,          // 新增：原 blendColor 派生值前置到解析期
    val candidateBackground: Int,
    val candidateTextColor: Int,
    val candidateHighlightColor: Int,
    val preeditTextColor: Int,
    val borderColor: Int,
    val keyShadowColor: Int,
    // —— 尺寸 / 字体 / 效果（新增能力）——
    val keyCornerRadiusDp: Float,
    val keyGapDp: Float,
    val keyboardPaddingDp: Float,
    val keyHeightScale: Float,
    val keyBorderWidthDp: Float,
    val keyTextSizeSp: Float,
    val funcTextSizeSp: Float,
    val candidateTextSizeSp: Float,
    val preeditTextSizeSp: Float,
    val typeface: Typeface?,             // null = 系统默认
    val keyStyle: KeyStyle,              // FILLED / OUTLINE / FLAT
    val keyShadow: ShadowSpec?,          // null = 关闭
    val backgroundAlpha: Float,
    val backgroundImage: Bitmap?,        // 已按 scaleMode 预处理；null = 纯色
    val backgroundDim: Float,
    val isDark: Boolean
)
```

设计要点：

- 颜色字段名与旧 `KeyboardTheme` 完全一致 → 视图迁移是**机械替换**（import + 类型名），
  绘制逻辑（`rebuildPaints`、`onDraw`）不动，满足"不影响键盘视图核心逻辑"。
- 所有派生计算（funcKey 混色、dark 变体选取、覆盖合并）前置到解析期，
  `rebuildPaints` 从"计算"退化为"赋值"，比现状更轻。
- `Bitmap`/`Typeface` 由 `SkinAssetCache` 持有并复用，`SkinTheme` 仅持引用；
  快照本身无生命周期负担，可安全跨视图共享。

### 5.2 解析管线（线程模型）

```kotlin
// SkinManager 内部（伪代码）
@Volatile private var cached: SkinTheme? = null   // 内存快照，读路径无锁

fun getCurrentSkin(context: Context): SkinTheme =
    cached ?: buildSkinBlockingFallback(context)   // 冷启动兜底：内置皮肤纯色构建，无 IO 大头

suspend fun rebuildSkin(context: Context): SkinTheme = withContext(Dispatchers.IO) {
    val spec     = repository.loadSpec(currentId)            // 读 skin.json（IO 线程）
    val override = repository.loadOverride(currentId)
    val resolved = SkinResolver.resolve(spec, override, isSystemDark(context))  // 纯函数
    val bg       = assetCache.loadBackground(resolved)       // 解码 + 预缩放（IO 线程）
    val font     = assetCache.loadTypeface(resolved)
    SkinTheme(resolved, bg, font).also { cached = it }
}
```

- **读热路径**（`buildInputView` 每次重建时取皮肤）：命中快照直接返回，O(1) 无 IO。
- **写路径**（切换/导入/自定义保存）：后台线程构建新快照 → 主线程 `setInputView(buildInputView(...))`。
- 冷启动（Service 首次 `onCreateInputView` 时快照未就绪）：同步走**轻量快照路径**
  （无 Bitmap 解码；内置皮肤纯内存，导入皮肤规格命中进程级 specCache 时亦纯内存，
  首次仍有一次 skin.json 读盘，见 §11 修订 R4），
  真实皮肤就绪后经 Handler 触发一次视图重建——与 Rime 引擎“异步部署 + 就绪重同步”的既有模式一致。

## 6. 皮肤资源管理 API 设计

### 6.1 `SkinManager`（门面，取代 ThemeManager 全部调用点）

```kotlin
object SkinManager {
    /** 当前皮肤快照（内存缓存命中 O(1)；未命中时内置皮肤兜底，从不返回 null）。 */
    fun getCurrentSkin(context: Context): SkinTheme
    fun getCurrentSkinId(context: Context): String

    /** 切换皮肤。校验存在性 + 等级解锁；成功后后台重建快照并回调。 */
    fun setSkin(context: Context, skinId: String, onReady: (SkinTheme) -> Unit = {}): Boolean

    /** 深浅色跟随：系统 uiMode 变化时由 Service onConfigurationChanged 调用，必要时重建快照。 */
    fun onSystemDarkModeChanged(context: Context, isDark: Boolean)

    /** 列表 / 解锁（沿用 LevelEngine，内置皮肤保留原解锁等级，导入皮肤默认 Lv.1）。 */
    fun getInstalledSkins(context: Context): List<SkinInfo>   // id/name/author/isBuiltin/预览路径
    fun getUnlockedSkinIds(context: Context): List<String>
    fun isSkinUnlocked(context: Context, skinId: String): Boolean

    /** 皮肤变更监听（设置页与 Service 各自注册，弱引用持有）。 */
    fun addListener(l: SkinChangeListener); fun removeListener(l: SkinChangeListener)
}
```

### 6.2 `SkinPackLoader`（安装 / 卸载）

```kotlin
object SkinPackLoader {
    /** 从 Uri 导入 .zyskin：临时目录解压 → 安全校验 → SkinSpecValidator → 原子落盘 → 更新索引。 */
    suspend fun install(context: Context, source: Uri): SkinInstallResult
    /** 卸载：删除安装目录 + 索引 + 该皮肤的用户覆盖；若为当前皮肤，回退内置默认皮肤。 */
    suspend fun uninstall(context: Context, skinId: String): Boolean
    /** 首次启动 / 版本升级时把 assets/skins/ 内置皮肤部署到 filesDir（AssetDeployer 同款增量模式）。 */
    suspend fun deployBuiltins(context: Context)
}

sealed class SkinInstallResult {
    data class Success(val info: SkinInfo) : SkinInstallResult()
    data class Invalid(val errors: List<String>) : SkinInstallResult()  // 校验错误明细，可展示
    data class Failed(val cause: String) : SkinInstallResult()
}
```

### 6.3 `SkinCustomizer`（用户自定义）

```kotlin
object SkinCustomizer {
    fun getOverride(context: Context, skinId: String): SkinOverride      // 稀疏覆盖
    fun saveOverride(context: Context, skinId: String, o: SkinOverride)  // 保存后触发快照重建
    fun resetOverride(context: Context, skinId: String)
    /** 编辑器实时预览：不落盘，直接用临时覆盖合成快照供 SkinPreviewRenderer 渲染。 */
    fun previewWith(context: Context, skinId: String, o: SkinOverride): SkinTheme
}
```

可自定义维度（皮肤编辑器 UI 暴露）：全部颜色（取色器）、圆角/键距/内边距/键高（滑杆）、
三区字号（滑杆）、阴影开关、键面透明度、背景图（从相册选图 → 复制入覆盖专用目录）、深浅色偏好。

### 6.4 `SkinAssetCache`（缓存管理）

```kotlin
object SkinAssetCache {
    /** 背景图：按 (skinId, 目标尺寸, dark) 键控 LruCache；解码时 inSampleSize 预降采样到屏宽。 */
    fun loadBackground(resolved: ResolvedSkin): Bitmap?
    /** 字体：Typeface 进程级缓存（Typeface 本身可安全长持有）。 */
    fun loadTypeface(resolved: ResolvedSkin): Typeface?
    /** 预览图：设置页网格用，LruCache（上限 8 张，约 720×480×4B ≈ 1.4MB/张）。 */
    fun loadPreview(info: SkinInfo): Bitmap?
    /** 皮肤卸载 / 切换时定向失效。 */
    fun evict(skinId: String)
}
```

内存预算：任意时刻常驻 = 当前皮肤 1 张背景图（解码期按屏宽 inSampleSize 预降采样）
+ 1 个 Typeface；背景图 LruCache 上限 8MB、预览图 LruCache 上限 8MB（见 §11 修订 R1），
预览缓存仅设置页在前台时增长，Activity 销毁时 trim。

### 6.5 `SkinPreviewRenderer`（预览）

复用 `TextImageRenderer` 的离屏 Canvas 模式：给定 `SkinTheme`，绘制一个 3 行迷你 QWERTY +
候选栏示意（不实例化真实 View），输出 Bitmap。用途：

1. 设置页皮肤网格缩略图（导入皮肤优先用包内 `preview.png`，缺失时现渲）；
2. 自定义编辑器的**实时预览**（每次滑杆变更 → `previewWith` 合成临时快照 → 重渲，纯内存无 IO）。

### 6.6 持久化布局

```
SharedPreferences("ziyou_skin")
├── current_skin_id        : String   # 当前皮肤 id（默认 "builtin.float3d"）
├── installed_index        : String   # 已安装皮肤索引 JSON（id→name/version/isBuiltin）
├── override.<skinId>      : String   # 各皮肤的用户覆盖稀疏 JSON
└── dark_mode_policy       : String   # followSystem / forceLight / forceDark
```

**键盘整体背景图的绘制归属**：背景图绘制在 Service 层 `contentLayout`（根 LinearLayout）的
background 上（一个预处理好的 `BitmapDrawable` + dim 层），键盘/候选/编码区在其上以
`backgroundAlpha` 调制键面色透明度——各 View 不感知背景图，只需 `boardBgPaint` 支持 alpha，
改动面最小且悬浮/停靠两形态天然一致。

### 7.2 Service 层接入（`ZiYouInputMethodService`）

- `buildInputView(mode)`：`ThemeManager.getCurrentTheme(this)` → `SkinManager.getCurrentSkin(this)`，
  下发方式不变（构建期一次性 `applySkin`）；根容器设置背景 Drawable。
- `cycleTheme()` → `cycleSkin()`：`getUnlockedSkinIds` 循环 + `setSkin(onReady = { setInputView(buildInputView(displayModeCtrl.currentMode)); scheduleEngineSync() })`——
  完整复用现有"主题切换 = 视图重建 + 引擎重同步"路径，引擎编码/方案不受影响的保证不变。
- `onConfigurationChanged`：uiMode 深浅色变化时调 `SkinManager.onSystemDarkModeChanged`，
  若快照变更则走同一重建路径。

### 7.3 与 DisplayModeController / 悬浮形态兼容

- 皮肤尺寸全部以 **dp 语义**进入 `SkinTheme`，各 View 仍经既有 `dp2px/sp2px`（内含
  `scaleFactor`）转物理像素 → 悬浮形态 `FLOATING_SCALE` 统一缩放**自动作用于皮肤尺寸**，
  停靠形态保持 1.0 零影响，两形态无需皮肤感知。
- 悬浮背景图：`FloatingPanelContainer` 内容区套用同一背景 Drawable（按悬浮宽度另取一份
  预缩放缓存，`SkinAssetCache` 以尺寸键控天然支持）；`backgroundAlpha` 在悬浮场景正是
  游戏悬浮键盘半透明诉求的皮肤化出口。
- `DisplayModeController.Host` 回调协议、insets 计算不涉及皮肤，零改动。

### 7.4 等级体系兼容（`LevelEngine`）

- `LevelEngine.isThemeUnlocked(name, level)` 语义沿用，皮肤域调用处传内置皮肤的
  **展示名**（悬浮立体/Material…）保持解锁表不变；导入/自定义皮肤不在表中 → 默认 Lv.1 解锁
  （现有函数已内建此回退）。`:core-logic` 可选做一次纯改名 `isSkinUnlocked`（保留旧名委托），
  25 个既有测试不回归。

### 7.5 设置页与皮肤管理页

- `SettingsActivity` 现有"主题"行改为"皮肤"入口（遵循设置页功能入口既有规范），
  点击进入新 `SkinActivity`（纯代码布局，无 XML）：
  - **皮肤网格**：预览图 + 名称 + 解锁等级角标，当前皮肤高亮；点击 = 预览大图 + 「应用」；
  - **导入**：SAF 文件选择器选 `.zyskin` → `SkinPackLoader.install` → 结果 Toast（含校验错误明细）；
  - **长按**：卸载（内置皮肤不可卸载）；
  - **自定义编辑器**：滑杆/取色器分组（颜色 / 尺寸 / 字体 / 效果 / 背景），顶部实时预览图，
    「保存」写覆盖、「恢复默认」清覆盖。

## 9. 性能优化与兼容性处理

### 9.1 性能

| 关注点 | 措施 |
|--------|------|
| 输入热路径（processKey/onCommit） | 皮肤系统**完全不在热路径上**：绘制只读预建画笔；快照读取为 volatile 字段命中 |
| 皮肤切换耗时 | 解析 + 解码全在 IO 线程；视图重建复用既有 `setInputView(buildInputView)` 路径（与现有主题切换/形态切换同源，已被验证） |
| 背景图内存 | 解码期 `inSampleSize` 降采样到目标尺寸；可配 RGB_565；同刻仅 1 张常驻 |
| 每帧绘制成本 | 背景图为容器 background（系统级 Drawable 绘制，无逐帧解码）；OUTLINE/FLAT 键面反而少一次填充 |
| 自定义编辑器实时预览 | 纯内存合成 + 离屏迷你渲染，不触碰真实键盘视图与磁盘 |
| GC 压力 | `SkinTheme` 切换时才新建；画笔复用现有实例只改属性 |

### 9.2 兼容性与健壮性

| 场景 | 处理 |
|------|------|
| `specVersion` 高于应用支持 | 拒绝安装并提示升级应用；`minSpecVersion` 允许向后兼容声明 |
| skin.json 字段缺失 | 默认值链兜底（= 现行硬编码视觉），永不因缺字段崩溃 |
| 皮肤目录损坏 / 图片解码失败 | 快照构建捕获异常 → 回退内置默认皮肤 + 单次 Toast，当前皮肤 id 复位 |
| 深浅色 | `darkMode=both` 双套配色跟随系统；`light`-only 皮肤在深色系统下按用户策略（跟随/强制）处理 |
| 卸载当前皮肤 | 自动回退内置默认皮肤并重建 |
| 旧版本升级 | `ziyou_theme` 偏好一次性映射迁移；内置皮肤随版本号增量重部署（AssetDeployer 同款机制） |
| 悬浮 ↔ 停靠切换 | 皮肤尺寸走 dp×scaleFactor 既有链路，无专门适配 |

### 9.3 测试计划（38 用例基线只增不减）

- `:core-logic`（纯 JVM）：`SkinColor` 解析（合法/非法/带 alpha）；`SkinResolver` 合并优先级
  （默认 < spec < override）与 dark 变体选取；`SkinSpecValidator` 全量规则（范围/枚举/id 格式）；
  `SkinDefaults` 与内置皮肤色值一致性快照测试。
- `:app`（JVM，无设备）：`SkinPackLoader` zip-slip 拒绝 / 超限拒绝 / 白名单外条目拒绝 /
  损坏 json 回滚；`SkinRepository` 持久化与旧偏好迁移；`SkinManager` 损坏皮肤回退默认皮肤。

## 11. 实施修订记录（优化改进轮，P1-P4 落地后）

以下为皮肤模块优化改进轮实际落地的设计修正与增强，以本节为准（与正文早期描述冲突时）：

| 编号 | 修订 | 说明 |
|------|------|------|
| R1 | 缓存预算修正 | `SkinAssetCache` 早期实现的背景图缓存实为 32MB、预览缓存 ≈ 44MB，与注释意图不符；已改为各 8MB（背景：当前 + 编辑器预览各 1 张降采样图；预览：约 8 张半屏宽缩略图）。`typefaceCache` 由非线程安全的 `mutableMapOf` 改为 `ConcurrentHashMap`（IO 协程与主线程并发读写）。 |
| R2 | 快照原子化 | `SkinManager` 的 `cached` + `cachedKey` 双 volatile 字段存在 (theme, key) 错位配对竞态，已合并为单个不可变 `Snapshot(theme, key)` 的 volatile 字段，读写各一次原子访问。 |
| R3 | 索引损坏自愈 | `SkinRepository.readIndex` 索引 JSON 损坏时不再静默清空，改为扫描 `skins/` 下含合法 skin.json（且目录名 = 规格 id）的安装目录重建索引并回写；单目录解析失败仅跳过。 |
| R4 | 规格进程级缓存 | `SkinRepository.loadSpec` 增加 `specCache`（ConcurrentHashMap）：导入皮肤的 skin.json 解码产物首次读盘后常驻内存，读热路径轻量构建趋近纯内存；安装/卸载时经 `evictSpec` 定向失效。故“冷启动无 IO”严格说法为：内置皮肤纯内存；导入皮肤首次一次读盘，后续纯内存。 |
| R5 | 变更类型感知的增量切换 | 新增 `SkinChangeKind { FULL, STYLE_ONLY }`：重建完成时比较新旧快照，仅样式字段（颜色/字号/圆角/描边/风格/透明度）变化且背景图 Bitmap、Typeface 引用与布局类尺寸（键高/间距/内边距）、背景节点（图/缩放/压暗）均未变时为 STYLE_ONLY。Service 在停靠形态下对现有视图原地 `applySkin` 跳过全量重建（保留输入状态）；悬浮形态及其余情况仍走 `setInputView(buildInputView)` 全量路径（保守策略）。监听器新增带 kind 的默认方法重载，既有 lambda 实现兼容。 |
| R6 | 编辑器预览防卡顿 | `SkinCustomizer.previewWith` 增加 `includeAssets` 参数（默认 true）：滑杆拖动中传 false 走纯样式合成零 IO，松手后传 true 补齐背景图/字体完整预览。 |
| R7 | 测试补齐 | 新增纯 JVM 用例 19 个：`SkinChangeKindTest`（变更判定）、`SkinManagerTest`（快照命中/失效/回退）、`SkinRepositoryIndexTest`（索引自愈/幽灵剔除/同 id 覆盖）、`SkinRepositorySpecCacheTest`（规格缓存/定向失效）；配套 `FakeSkinContext`（内存 prefs + 临时目录）测试替身。 |
