### 2.3 新增:数字编码自定义短语(自建 custom_phrase_t9)

frost 上游 `rime_frost_t9` 引用的 `custom_phrase_t9.txt` 在其仓库中**不存在**
(已实证),自建最小集:高频单字/词的九键整码直出(如 96=我、6446625=明白),
`initial_quality: 99` 保证置顶。

```yaml
translators:
  # ...既有三项之后追加(script_translator 之前优先匹配)
  - table_translator@custom_phrase

custom_phrase:
  dictionary: ""
  user_dict: custom_phrase_t9
  db_class: stabledb
  enable_completion: false
  enable_sentence: false
  initial_quality: 99
```

文件 `assets/rime/custom_phrase_t9.txt` 首版约 30~50 条,来源:白霜 8105 字频
Top 单字的九键整码 + 超高频二字词。**编码必须是纯数字**(九键 prism 无字母路径)。

## 3. 目标二:Lua 功能对齐

### 3.1 集成清单(T9 Lua 四件套)

| 脚本 | 挂载点 | 功能 | 依赖 |
|------|--------|------|------|
| `corrector.lua` | `lua_filter@*corrector` | 错音错字提示(输 gei yu 显示「给予 ji yu」) | corrections 四列表(就绪)+ comment ［］包裹契约 |
| `is_in_user_dict.lua` | `lua_filter@*is_in_user_dict` | 用户词加 `*`、联想句加 `∞` 标记 | 无 |
| `force_gc.lua` | `lua_translator@*force_gc` | 每次查询步进 GC,抑制大词库+lua 内存增长 | 无 |
| ~~select_character~~ | ~~lua_processor~~ | 以词定字 | **排除**:依赖 key_binder 字母快捷键,九键无字母键 |

filter 顺序(与全拼 rime_frost 对齐):
`is_in_user_dict → corrector → simplifier@emoji → simplifier@zh_trad → uniquifier`。

### 3.2 corrector 挂载的配套契约(关键)

`corrector.lua` L57 以 `cand.comment:match("^［(.-)］$")` 判定输入,因此 T9
translator 必须补:

```yaml
translator:
  spelling_hints: 100             # 32 → 100,对齐 frost t9,提升 comment 覆盖
  always_show_comments: true      # corrector 判定依赖
  comment_format:
    - xform/^/［/
    - xform/$/］/
```

**代价**:`PinyinHintProvider` 的 comment 回退路径将收到 `［…］` 包裹文本,被其
白名单(仅字母/`'`/空格)丢弃 → 回退路径实质失效。评估结论:**可接受**——
主路径用 `T9PinYinUtils` 本地还原数字段(精确、与词库/comment 无关),回退路径
仅在输入串无数字段时兜底,九键场景极少触发。13 个 `PinyinHintProviderTest`
用例(其中含空上下文/回退路径用例)作回归门禁。

### 3.3 明确不集成项及理由

| 项 | 理由 |
|----|------|
| `aux_lookup_filter`(句中辅助码) | 触发前缀 `` ` `` 不在九键键面;墨奇码拆分表(moqi_chaifen)43MB 级,九键收益为零 |
| `pin_cand_filter` | 固顶表以**拼音编码**匹配,九键输入为数字编码,永不命中,挂载纯开销 |

## 4. 目标三:配置优化

### 4.1 algebra 对比结论:ziyou 为功能超集,不采纳 frost t9 规则

逐条对比 `rime_frost_t9.schema.yaml` 与 ziyou `t9.schema.yaml` 的 speller.algebra:

| frost t9 规则 | ziyou 对应 | 决策 |
|---------------|-----------|------|
| `abbrev` 超级简拼 ×2 | 已有(等价) | 保持 |
| `derive/^([nl])ve$/` `derive/^([jqxy])u/` | **2.8 版已移除** | **不回补**:九键下 u/v 同属 8 键、ve/ue 同码,数字消歧天然覆盖(t9.schema.yaml L82-84 有实证注释),回补徒增棱镜边数 |
| 容错 derive ×8(无标签) | 已有(带 `/correction` 权重标签) | **保持 ziyou 版**:无标签 derive 曾致模糊匹配与精确匹配同权的排序事故(L94-97),禁止回退 |
| 数字映射 `derive/[hgi]/4` 等 | 已有(`[ghi]/4`,集合等价) | 保持 |
| fuzz 模糊音(ziyou 独有) | `/fuzz` 半权标签 | 保持(frost 无此能力) |
| 换位容错 ×10(ziyou 独有) | 见 L106-115 | 保持(frost 无此能力) |
| 英文 0 标记降级链(ziyou 独有) | `abbrev/^0(.+)$/ + erase/^0.*$` | **保持,严禁触碰**(缺失将致输 65 中文候选消失) |

### 4.2 采纳的优化项(仅两处)

1. `spelling_hints: 32 → 100`:提升多音节词 comment 覆盖,corrector 判定与
   未来候选注音展示受益;
2. `translator.comment_format` ［］包裹 + `always_show_comments: true`:
   corrector 契约配套(见 3.2)。

### 4.3 状态机契约保持(零改动论证)

| 组件 | 依赖契约 | 本计划影响 |
|------|----------|-----------|
| `KeyRecordStack` | 数字键进 prism、`'` 分词、replaceKey 原地替换 | **零影响**:不动 algebra 数字映射/delimiter/key_binder |
| `PinyinHintProvider` 主路径 | `T9PinYinUtils` 本地还原 | **零影响**:与引擎配置无关 |
| `PinyinHintProvider` 回退路径 | 候选 comment 为纯拼音 | **降级失效**(见 3.2 代价评估):comment 被 ［］ 包裹或 `*`/`∞` 替换,白名单丢弃;主路径兜底,13 用例回归 |
| `NineGridKeyboardView` | 功能列布局/分词键 | **零影响**:不引入 frost 的 1 键分词交互 |

## 6. 技术冲突点与对策

| # | 冲突点 | 影响 | 对策 |
|---|--------|------|------|
| 1 | **comment ［］包裹 vs PinyinHintProvider 回退路径** | 回退路径失效 | 白名单天然丢弃包裹文本,无异常;主路径承载;新增 3 个守护用例;若真机发现侧栏提示命中率显著下降,可单独回滚 comment_format(corrector 同步下线) |
| 2 | **is_in_user_dict 改写 comment 为 `*`/`∞`** | 同上,回退路径收不到拼音 | 同 #1;UI 收益(用户词可见标记)大于回退路径损失 |
| 3 | **corrector 读 user dir 的 corrections 文件** | `rime_api.get_user_data_dir()/cn_dicts/corrections.dict.yaml` 路径 | **已实证冲突成立**：librime-lua `types.cc` L69-70 的 `get_user_data_dir()` 直接返回 traits 的 user_data_dir（即 `rime_user/`，不含 shared dir 回退），而 corrections 部署在 `files/rime/`，照搬 frost 脚本将读到空表静默失效。**解法（T0 落地）**：`AssetDeployer.performDeploy` 追加一行，将 `cn_dicts/corrections.dict.yaml` 同步复制到 `rime_user/cn_dicts/`（升版覆盖式，与 shared dir 双写保持一致）；不改上游 lua 脚本，保留后续同步能力 |
| 4 | **custom_phrase_t9 数字编码进入 prism** | 与 0 标记英文链/中文数字消歧同码竞争 | initial_quality 99 仅影响排序;编码为纯数字不产生新字母路径;验证用例:输 96 首候选为「我」且中文候选不消失 |
| 5 | **emoji 候选混入九键候选栏** | 候选 comment 为空/emoji,触摸选词索引错位风险 | `inherit_comment: false`;`SimpleCandidatesView` 渲染纯文本无碍;`KeyRecordStack` 只追踪击键不追踪候选,零影响;默认 emoji 开关关闭(states 首态 💀=关),用户显式开启才生效 |
| 6 | **force_gc 挂载为 translator** | 每次查询多一个 translator 轮询 | frost 全量用户实测惯例,单步 GC 开销微秒级;性能基准盯单键 P95 |
| 7 | **部署时序**:新 lua/表文件需先于引擎启动落盘 | 旧版部署状态缺文件 → lua 加载报错 | versionCode 升版强制重部署(现有机制);lua 文件缺失时 librime-lua 报 error 但方案不崩(降级为无该组件) |
