# 联想功能重构方案

> 状态：**已被第 11 节决策取代** —— 应用层联想管线已整体移除，转纯引擎级（librime-predict）路线。
> 第 1-10 节保留为历史设计记录，现行架构以第 11 节与 ARCHITECTURE.md「联想输入」小节为准。
> 范围：`:core-logic` `com.ziyou.ime.core.association` / `:app` 联想相关模块
> 前置阅读：[ARCHITECTURE.md](../ARCHITECTURE.md)「联想输入」小节

## 1. 背景与问题分析

### 1.1 yuyansdk 联想实现的评估结论

| 维度 | 实现方式 | 问题 |
|---|---|---|
| 触发 | `onUpdateSelection`（编辑器光标/内容变化回调） | 覆盖广但频率不可控：光标每移动一次都触发完整联想查询，无防抖 |
| 数据源 | 私有 fork librime 的 `Session::GetAssociateWord`（词典汉字前缀检索）+ `CustomEngine` 标点/日期规则 | 核心能力锁死在**闭源 native 补丁**中，上游 librime 无此 API，不可移植 |
| 线程 | 无线程基础设施，`getTextBeforeCursor`（同步 IPC）+ JNI 词典检索**全在 UI 线程** | 主线程阻塞风险，词典大时可感知卡顿 |
| 缓存 | 无 | 重复上屏同词、光标来回移动时全量重查 |
| 状态 | `DecodingInfo.isAssociate` 全局单例 + `RimeEngine.customPhraseSize` 跨对象索引修正 | 三段拼接列表（Rime 前 5 + 自定义 + Rime 其余）与 `index - customPhraseSize` 的选择索引存在错位隐患 |
| 个性化 | 无（仅依赖词典静态权重） | 联想排序不随用户习惯变化 |

### 1.2 ziyou-ime 首版实现（重构前）的不足

首版（`AssociationEngine` 单体 + `AssociationManager`）已解决 yuyan 的线程/缓存/索引问题，但仍有：

1. **单体引擎不可扩展**：词组匹配与标点规则耦合在一个 `object` 里，新增数据源（日期、用户学习、未来引擎预测）只能继续往里堆分支；
2. **无个性化**：静态 `association.json` 排序固定，联想准确性无法随使用提升——这是对 yuyan 最有价值的超越点，首版未覆盖；
3. **缺少日期联想**：yuyan 的 `chinese_association_date` 能力未对齐；
4. **缓存失效粗糙**：（引入学习后）数据变化时无精准失效机制。

## 2. 重构设计原则

1. **数据源可插拔**：联想能力 = 「N 个数据源 × 1 个合并管线」，每个数据源独立启停、独立单测；
2. **引擎预测预留位**：未来重编 librime 启用 predict 模块后，引擎预测出现在 commit 后的 `context.menu` 中，走既有候选渲染路径（`updateUI` 的 `hasMenu` 分支天然优先于应用层联想），应用层数据源自动降级为补充源，**管线结构无需改动**；
3. **热路径零磁盘 IO**（沿用项目原则 6）：学习埋点仅做 O(1) 内存操作，防抖落盘；
4. **对外 API 兼容**：`AssociationManager` 门面（`isEnabled` / `associate` / `preload`）签名不变，`InputLogicController` / Service / 设置页的既有调用零成本迁移；
5. **隐私边界明确**：学习数据仅为 1-4 字汉字词对计数（不含语句上下文），仅存本机，可关闭、可清除。

### 3.2 核心接口定义

```kotlin
// 数据源抽象（:core-logic）
fun interface AssociationSource {
    fun associate(committedText: String): List<String>
}

// 合并管线（:core-logic）
class AssociationPipeline(
    wordSources: List<AssociationSource>,    // 词组类源，列表顺序即优先级
    middleSources: List<AssociationSource>,  // 补充源（日期/标点），插在词组前5之后
    limit: Int = DEFAULT_LIMIT               // 默认 10
) { fun associate(committedText: String): List<String> }

// 用户学习模型（:core-logic，线程安全）
class UserBigramModel(maxHeads = 500, maxTailsPerHead = 8) {
    fun record(prev: String, next: String)       // 非法词静默忽略
    fun tailsFor(prev: String): List<String>     // 频次降序
    fun snapshot(): Map<String, Map<String, Int>>
    fun restore(data: Map<String, Map<String, Int>>)
    fun clear(); fun size(): Int
}

// IME 层埋点（InputLogicController.Callbacks 新增）
fun onTextCommitted(text: String)   // 统一上屏出口 commitAndCount 驱动
```

### 3.3 合并策略（与 yuyan 对齐）

```
词组联想（用户学习 > 静态表，去重保序）前 5 个
  → 日期联想（开关开且命中日期词）
  → 标点联想（！/？置首规则）
  → 其余词组联想
  → 截断 limit(10)
```

门控：上屏文本非汉字结尾 → 返回空（终止「选标点 → 再联想」死链）。

## 4. 关键流程

### 4.1 联想触发（事务内，规避 yuyan 的 UI 线程与竞态问题）

```
processKey/selectCandidate 上屏 commit
  → updateUI(committedText)                       [inputMutex 事务内]
      ├─ context.menu 非空 → 正常候选渲染（未来引擎预测走此分支）
      └─ menu 空 && committedText != null && 开关开
           → loadAssociations（LRU 命中 O(1)）
           → renderAssociations（主线程，强调色整栏展示）
```

### 4.2 用户学习（热路径 O(1) + 防抖落盘）

```
commitAndCount(text)
  → callbacks.onTextCommitted(text)
  → AssociationManager.recordCommit
      ├─ 学习开关关 → 重置词对窗口，返回
      ├─ 距上次上屏 ≤ 10s → userModel.record(prev, text)   [内存 O(1)]
      │     ├─ queryCache.remove(prev)                     [精准失效]
      │     └─ 累计 20 次 → persist（SharedPreferences apply 异步写盘）
      └─ 更新 lastCommit 窗口
flush 时机：onFinishInputView / onDestroy（与 LevelStats.flush 同点位）
```

### 4.3 选择联想词

```
点击候选 → Service 按 inputLogic.isAssociating 路由
  → selectAssociation(index)
      ├─ commitAndCount(word)        → 自动触发学习埋点（词对成链）
      └─ loadAssociations(word)      → 非空继续链式联想 / 空则清栏
```

## 5. 性能与容量预算

| 项 | 预算 | 说明 |
|---|---|---|
| 联想查询 | 缓存命中 O(1)；未命中 ≤ 8 次 map 查找 + ≤10 元素排序 | 主线程可承受（μs 级） |
| 学习埋点 | O(1) map 计数 | 每次上屏一次 |
| 落盘 | ≤ 500×8 词对 JSON（几十 KB），每 20 次学习/视图隐藏时 `apply()` | 异步写盘，不阻塞输入 |
| 内存 | 静态表 ~200 词条 + 学习模型 ≤ 4000 词对 + LRU 128 条查询缓存 | < 1MB |

## 7. 迁移策略与风险控制

1. **API 兼容迁移**：`AssociationManager.isEnabled/setEnabled/associate/preload` 签名不变；`AssociationEngine` 被 `AssociationPipeline` + 各数据源取代（内部实现，无外部引用泄漏），调用方仅 `InputLogicController.Callbacks` 新增 `onTextCommitted` 一处扩展。
2. **数据兼容**：首版无持久化学习数据，无迁移负担；`association.json` 格式不变。
3. **回滚路径**：三个开关均可独立关闭；全关时行为等价于「无联想」，学习数据可一键清除。
4. **风险点与对策**：
   - 学习污染（误选词被记住）→ 频次排序 + 后续词容量淘汰自然稀释；可手动清除；
   - SharedPreferences 体积 → 模型端硬上限 500×8，序列化几十 KB；
   - 隐私 → 仅 1-4 字汉字词对计数，`UserBigramModel.isLearnableWord` 强制过滤，本机存储。

## 10. 决策记录：predict 启用后应用层管线的定位（已评估）

### 10.1 能力重叠度分析

| 能力 | librime-predict | 应用层管线 | 结论 |
|---|---|---|---|
| 通用下一词预测 | ✅ predict.db 大规模语料，质量高 | ⚠️ 静态 association.json（~200 条手工维护） | **重叠**，启用后静态表降级为兜底 |
| 个性化学习 | ❌ predict.db 只读，插件无学习机制 | ✅ UserBigramModel 词对频次 | **应用层独有** |
| 日期/星期联想 | ❌ | ✅ DateAssociationSource | **应用层独有** |
| 标点联想 | ❌（源码中 `last_commit.type=="punct"` 时主动清预测） | ✅ PunctuationAssociationSource | **应用层独有** |
| 链式联想 | ✅ max_iterations 限轮 | ✅ 标点终止链 | 重叠，引擎优先 |
| 可用性 | ❌ 当前未编入预编译库（WITH_PREDICT=OFF） | ✅ 已上线 | 启用前应用层是唯一来源 |

**决策：保留应用层管线，重定位为「个性化 + 规则补充 + 兜底」**：不可移除（三项独有能力 +
启用前的唯一来源 + 启用后引擎不产出时的兜底）；仅静态词组表在启用后自然降级
（hasMenu 分支优先，无需改代码）。

### 10.2 融合机制（PredictionFusion，纯逻辑已实现 + 单测）

优先级为固定规则（非数值权重，避免不可解释的排序抖动）：

```
1. 用户学习词置顶（≤ 2 个）—— 个性化 > 通用语料；
   与引擎词重叠时保留引擎身份（FusedCandidate.fromEngine=true + engineIndex），
   点击走 Rime selectCandidate 反哺引擎词频与 commit 历史，维持引擎链式预测语义
2. 引擎预测词按引擎原序（predict.db 语料频次序）
3. 应用层补充词（日期/标点）殿后
去重（首现胜）、截断 10 条；engineWords 为空时退化等价于现有应用层组合
```

点击路由：`fromEngine=true` → `selectCandidate(engineIndex)`；`false` → 直接上屏（selectAssociation 路径）。

## 11. 最终决策：移除应用层管线，转纯引擎级路线（本文档现行状态）

应用户对代码简洁性的要求，第 10 节的「保留 + 融合」方案被替换为纯引擎级路线，
以下组件已整体移除：

- `:core-logic`：AssociationPipeline / AssociationSource（含标点、日期源）/
  BigramAssociationSource / UserBigramModel / PredictionFusion 及全部联想单测；
- `:app`：UserAssociationRepository、assets/association.json，AssociationManager 瘦身为单一开关；
- IME 层：InputLogicController 的联想触发/选择/链式逻辑与 onTextCommitted 埋点、
  Service 的联想渲染/点击路由/预热/flush、SimpleCandidatesView.showAssociations、
  设置页日期/学习开关与清除入口。

**保留的引擎集成（启用 predict 后直接工作）**：
- `AssociationManager` 联想开关 → Rime 选项 `prediction` 联动（applyEngineForKeyboard）；
- `renderContext` 预测态识别（菜单非空且 input 为空）→ 候选栏强调色整栏绘制；
- 引擎预测经 `context.menu` 走既有候选渲染与 Rime 选词路径（含链式预测与
  BackSpace/Escape 清预测，均由 predictor 处理）。

**影响与风险（已知并接受）**：
- ~~在完成 native 重编之前联想功能整体不可用~~ → **已启用**：WITH_PREDICT=ON 重编完成、
  双侧开关一致、schema 已挂载、官方 predict.db（data-1.0，7.2MB）经 assets 随升版部署到用户目录；
- 个性化学习、日期/标点联想能力随应用层管线一并移除（predict.db 只读、
  predictor 在标点上屏时主动清预测，这些能力引擎不提供）；
- 旧版遗留的 SharedPreferences 键（日期/学习开关、学习数据）无害残留，不再读取。

**启用实施记录（已完成）**：插件源码 clone 到 `librime-prebuilt/plugins/librime-predict` →
 superbuild 修复（插件 objs 补链 Boost 使用要求 + BUILD_TOOLS=OFF）→ `WITH_PREDICT=ON ./build.sh
 arm64-v8a` 重编并验证符号 → app gradle `-DWITH_PREDICT=ON` + versionCode 升版 → 两套 schema
 挂载 predictor/predict_translator/prediction 开关 + predictor 配置 → AssetDeployer 部署
 predict.db 到用户目录 → assembleDebug 链接验证（.so 含 Predictor 代码、APK 含 predict.db）。
