# 符号键盘调研与设计方案

> 字由输入法（ziyou-ime）符号键盘功能的市场调研报告与技术设计文档。

## 一、市场调研

### 1.1 调研对象与方法

选取国内外 6 款主流输入法，围绕「符号分类方式、面板布局、交互方式、自定义能力」四个维度进行对比：

| 输入法 | 平台 | 调研版本形态 |
|---|---|---|
| 搜狗输入法 | Android/iOS | 中文主流商业输入法 |
| 百度输入法 | Android/iOS | 中文主流商业输入法 |
| 讯飞输入法 | Android/iOS | 中文主流商业输入法 |
| Google Gboard | Android/iOS | 国际主流输入法 |
| 微软 SwiftKey | Android/iOS | 国际主流输入法 |
| iOS 系统键盘 | iOS | 系统级参照 |

### 1.2 符号分类方式对比

| 输入法 | 分类维度 | 典型分类 |
|---|---|---|
| 搜狗 | 左侧竖排分类导航 | 最近、常用、中文、英文、括号、数学、序号、货币、单位、箭头、拼音、注音、特殊、颜文字 |
| 百度 | 左侧竖排分类导航 | 常用、中、英、网络、数学、序号、单位、货币、希腊、俄文、注音、制表 |
| 讯飞 | 左侧竖排分类 + 顶部页签 | 常用、中文、英文、数学、序号、标点、单位、货币、特殊、颜文字（与表情面板打通） |
| Gboard | 两级平铺（?123 → =\<） | 第一页：数字+常用标点；第二页：数学/货币/特殊符号；无中文分类概念 |
| SwiftKey | 两级平铺（123 → {&=） | 与 Gboard 类似的两页制；长按数字键出扩展符号 |
| iOS 系统键盘 | 两级平铺（123 → #+=） | 两页制；中文键盘额外有「符」面板带竖排分类 |

**结论**：
- 中文输入法（搜狗/百度/讯飞）高度一致地采用 **「左侧竖排分类导航 + 右侧符号网格」** 结构，分类数量 10~14 个；
- 国际输入法（Gboard/SwiftKey）因西文符号总量少，采用 **两级平铺换页制**，不设分类导航；
- 中文场景下符号量大（全角/半角、中文标点、序号、数学……），**分类导航是事实标准**；
- 「常用/最近」几乎是所有中文输入法的第一分类，且默认落位，命中率最高。

### 1.3 交互方式对比

| 交互点 | 搜狗 | 百度 | 讯飞 | Gboard | SwiftKey |
|---|---|---|---|---|---|
| 进入方式 | 键盘「符」键 | 键盘「符」键 | 键盘「符」键 | ?123 键 | 123 键 |
| 分类切换 | 左栏点按（竖排滚动） | 左栏点按 | 左栏点按/页签 | 换页键 | 换页键 |
| 符号上屏后 | 停留面板（可连续输入） | 停留面板 | 停留面板 | 部分符号后自动回主键盘 | 停留 |
| 长按扩展 | 长按候选更多同类符号 | 长按收藏 | 长按收藏 | 主键盘长按出符号（hinted symbol） | 主键盘长按出符号 |
| 自定义常用 | 支持（自动学习+手动） | 支持 | 支持 | 不支持 | 不支持 |
| 最近使用 | 自动记录 | 自动记录 | 自动记录 | 无 | 无 |
| 退出方式 | 「返回」键回原键盘 | 「返回」键 | 「返回」键 | ABC 键 | ABC 键 |
| 面板内删除/回车 | 有 ⌫/↵ | 有 | 有 | 有 | 有 |

### 1.4 各输入法优缺点小结

**搜狗输入法**
- 优点：分类最全（14 类）；「最近+常用」双分类命中率高；连续输入体验流畅；符号锁定（连打）设计成熟。
- 缺点：面板信息密度大、视觉较拥挤；部分分类（注音、制表）使用率极低仍占导航位。

**百度输入法**
- 优点：左栏分类+右侧网格的信息层级清晰；长按收藏交互路径短。
- 缺点：常用符号自动学习不透明，用户可控性弱；分类顺序不可调。

**讯飞输入法**
- 优点：符号与颜文字/表情面板打通，入口统一；支持符号搜索。
- 缺点：面板层级多（页签+左栏），首次学习成本高。

**Gboard**
- 优点：两页制极简，西文场景零学习成本；主键盘长按出符号减少面板切换。
- 缺点：无中文标点分类，中文全角符号输入弱；无常用/最近，重复查找成本高。

**SwiftKey**
- 优点：与 Gboard 类似的极简两页制；长按扩展丰富。
- 缺点：同样缺少中文分类与个性化。

**iOS 系统键盘**
- 优点：中文键盘的「符」面板同样验证了竖排分类范式；系统级一致性好。
- 缺点：不可自定义；分类少。

### 1.5 调研结论 → 字由输入法设计原则

1. **采用中文输入法事实标准**：左侧竖排分类导航 + 右侧符号网格 + 底部功能栏（返回/空格/退格/回车）。
2. **「常用」+「最近」置顶**：常用支持用户自定义（默认给出高频中文标点），最近自动记录（上限 30 个）。
3. **上屏后停留面板**：支持连续输入符号，点「返回」回到进入前的键盘布局。
4. **长按收藏**：网格内长按符号加入「常用」，在「常用」分类内长按移除——交互路径最短的自定义方式。
5. **符号数据源复用 Rime 配置**：分类内容优先从已部署的 `symbols.yaml`（`punctuator/symbols` 段）解析，与 Rime 生态保持同源；解析失败时回退内置符号集。
6. **不做的**：符号搜索（低频、成本高，留待后续）；颜文字/emoji（属表情体系，非本期范围）。

## 二、技术设计

### 2.1 总体架构

遵循项目既有五层架构与「View 组合拆分」实践：

```
SettingsActivity ──┐（常用符号管理入口）
                   ▼
┌────────────────────────────────────────────┐
│ data/SymbolCategory.kt                     │
│  ├─ SymbolCategory     分类数据模型          │
│  └─ SymbolRepository   分类/符号仓库          │
│      ├─ 内置分类：中文 / 英文 / 括号           │
│      ├─ YAML 分类：数学/序号/箭头/货币/星号/…  │
│      │    ← 解析已部署 rime/symbols.yaml     │
│      ├─ 常用：SharedPreferences + JSON       │
│      └─ 最近：SharedPreferences + JSON       │
└────────────────────────────────────────────┘
                   ▲
┌────────────────────────────────────────────┐
│ ime/SymbolKeyboardView.kt                  │
│  继承 BaseKeyboardView（主题/缩放/回调复用）    │
│  纯 Canvas 绘制三个区域：                     │
│  ┌──────┬───────────────────┐              │
│  │ 分类栏 │   符号网格（5列，可滚动）│           │
│  │(竖排可 │                   │              │
│  │ 滚动)  │                   │              │
│  ├──────┴───────────────────┤              │
│  │ [返回] [空格] [⌫] [↵]      │              │
│  └──────────────────────────┘              │
└────────────────────────────────────────────┘
                   ▲
KeyboardType.SYMBOL → KeyboardLayoutManager 登记
                   ▲
ZiYouInputMethodService：KEYCODE_SYMBOL 切换/返回、
符号直接上屏（InputLogicController.commitSideSymbol 同源出口）
```

### 2.2 数据结构

```kotlin
data class SymbolCategory(val id: String, val label: String)
```

分类清单（顺序即左栏展示顺序）：

| id | label | 数据源 |
|---|---|---|
| favorite | 常用 | SharedPreferences（用户自定义，默认高频中文标点） |
| recent | 最近 | SharedPreferences（自动记录，上限 30） |
| cn | 中文 | 内置 |
| en | 英文 | 内置 |
| bracket | 括号 | 内置 |
| math | 数学 | symbols.yaml `/sx` |
| num | 序号 | symbols.yaml `/szq` |
| arrow | 箭头 | symbols.yaml `/jt` |
| currency | 货币 | symbols.yaml `/hb` |
| star | 星号 | symbols.yaml `/xh` |
| geometry | 几何 | symbols.yaml `/jh` |
| unit | 单位 | symbols.yaml `/dw` |

### 2.3 性能设计

- **一次解析、全量缓存**：`symbols.yaml` 仅 234 行，首次访问在后台线程整体解析并缓存到内存（`preload()` 在 Service `onCreate` 时预热），后续访问零 IO。
- **可视区绘制**：符号网格只绘制滚动窗口内的行（起止行号由 scrollOffset 计算），单分类数百个符号也不产生额外绘制成本；命中检测用坐标反算行列，不缓存逐格 RectF。
- **符号直接上屏**：符号经 `InputLogicController.commitSideSymbol` 统一出口直接 commit，不经 Rime 编码路径，避免 punctuator 转换歧义（全角/半角由分类显式区分），也不受引擎繁忙影响。

### 2.4 与现有系统的集成点

| 集成点 | 方式 |
|---|---|
| 键盘类型 | `KeyboardType` 新增 `SYMBOL`，`SymbolKeyboardView` 与枚举命名对应 |
| 进入/退出 | 九宫格「符」键与 QWERTY 新增「符」键发送 `KEYCODE_SYMBOL`；Service 记录进入前布局，再按一次或点「返回」恢复 |
| 主题 | 继承 `BaseKeyboardView` 的 `applyTheme`/画笔体系，全部颜色取自 `KeyboardTheme` |
| 悬浮键盘 | 继承基类 `scaleFactor` 统一缩放，悬浮形态零额外适配 |
| 上屏 | 复用 `Callbacks.onSideSymbolInput → InputLogicController.commitSideSymbol`（等级计分、技能面板改道等横切逻辑自动生效） |
| 引擎状态 | 进入符号键盘时清除活跃编码；方案与 ascii_mode 保持不变，返回后无感恢复 |
| 设置页 | 「符号键盘 → 常用符号」管理入口，与「拼音侧栏符号」同样式的增删/恢复默认对话框 |
| 持久化 | 符号键盘为临时面板，不写入 `keyboard_type` 偏好，重启输入法回到进入前布局 |
